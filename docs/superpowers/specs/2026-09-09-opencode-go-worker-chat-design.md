# OpenCode Go Worker Chat Design

## Goal

Repurpose the existing Cloudflare Worker service associated with the `networkplushub` repository into a minimal AI backend for the Network+ app without changing the current Pages frontend or Supabase persistence flow.

## Scope

The Worker exposes exactly one application endpoint:

- `POST /chat`

Request body:

```json
{
  "message": "Explain subnetting"
}
```

Successful response:

```json
{
  "text": "...model response..."
}
```

This phase does not add a chat UI, chat history, Supabase reads/writes, authentication logic, streaming, tool calling, or multiple model selection.

## Architecture

```text
Network+ Pages frontend
        ↓ POST /chat
Cloudflare Worker: networkplushub
        ↓ HTTPS
OpenCode Go Responses API
        ↓
GPT-5.6 Luna
```

The Worker stores `OPENCODE_GO_API_KEY` as a Cloudflare Worker secret. The key must never be committed to GitHub or exposed to the Pages frontend.

## OpenCode Go Integration

Use:

- Model ID: `gpt-5.6-luna`
- Endpoint: `https://opencode.ai/zen/go/v1/responses`
- Stable conversation/session header: `x-opencode-session`
- Explicit user agent identifying this client

OpenCode Go documentation currently lists GPT-5.6 Luna on the Responses endpoint and requests that clients identify themselves and send a stable `x-opencode-session` header per conversation.

The Worker will call the OpenCode Go endpoint with a simple text input and normalize the provider response into `{ "text": "..." }` for the browser.

## Worker Behavior

- `POST /chat` accepts JSON.
- Reject missing or blank `message` with HTTP 400.
- Reject unsupported methods with HTTP 405.
- Respond to CORS preflight requests.
- Allow the Network+ custom domain and Pages preview domain to call the Worker.
- Call OpenCode Go with GPT-5.6 Luna.
- Return HTTP 502 when the upstream provider fails.
- Never return the API key or upstream authorization details.

## Deployment

The existing repository currently has no committed Wrangler configuration or Worker source. Add a minimal Worker scaffold to this same repository and configure its Worker name as `networkplushub` so Cloudflare's existing Worker service can use the same deployment target rather than creating another Worker.

The Pages build remains unchanged and continues serving the Vite app.

## Files

Planned additions:

- `worker/src/index.js` — Worker HTTP handler and OpenCode Go proxy logic.
- `worker/wrangler.jsonc` — Worker project configuration naming the existing `networkplushub` Worker.
- `worker/test/index.test.js` — request validation and upstream-response tests using mocked fetch.

No frontend source files are changed in this phase.

## Secret Setup

Required Cloudflare Worker secret:

```text
OPENCODE_GO_API_KEY
```

The user enters the value directly in Cloudflare or via Wrangler. The value is never requested in chat and never committed to the repository.

## Success Criteria

A POST request such as:

```json
{
  "message": "What is the OSI model?"
}
```

sent to the deployed Worker `/chat` endpoint returns HTTP 200 and JSON containing a non-empty `text` field generated by `gpt-5.6-luna` through OpenCode Go.
